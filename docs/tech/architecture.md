# Архитектура — PROPOSED
Движок, язык сервера и СУБД не выбраны. До выбора сравнить Android-экспорт, 2D/3D, размер сборки, профилирование, тестируемость, навыки команды и поддержку сервера.

Рекомендация для старта: Android-клиент + один модульный сервер + транзакционная БД на VPS. Модули: учётные записи, мир, экономика, очереди/марши, бой, альянсы, администрирование. Не начинать с микросервисов. PostgreSQL — кандидат, не принятое решение. Кэш/очередь сообщений добавлять при доказанной необходимости.

HTTP подходит для команд и снимков; push/WebSocket — кандидат для обновлений. После разрыва поток событий не заменяет ресинхронизацию. Конкретный транспорт OPEN.

Сервер — единственный источник состояния. Запись команды, изменение ресурсов и постановка задания согласованы транзакцией; выдача события наружу — после фиксации, при необходимости через transactional outbox. Worker может перезапускаться; задача имеет устойчивый идентификатор и защиту от повторной обработки.

Предметная симуляция отделена от сети и отображения, время внедряется как зависимость. Это позволяет воспроизводить таймеры и бои без Android. Версии правил, состояния и API явные. Обновление таблиц не меняет уже запущенные задания непредсказуемо: политику фиксации версии определить в P01-02.

VPS остаётся одной точкой отказа в первом варианте. Масштабирование начинается с измерений БД/worker и разделения миров, не с обещания выдержать MMO на неизвестном сервере.
