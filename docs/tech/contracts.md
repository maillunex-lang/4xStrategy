# Доменные и сетевые контракты — PROPOSED, без привязки к стеку
## Сущности
Account, Session, World, Membership, Settlement, ResourceBalance, Building, Job, Army, March, BattleReport, Alliance. У сущности устойчивый ID; публичные ID не дают прав доступа. Игрок принадлежит миру через Membership.

## Команда
Поля: `request_id`, `command_type`, `payload`, при необходимости `expected_revision`. Идентичность и права выводятся из проверенной сессии, не из переданного `player_id`. Сервер связывает ключ идемпотентности с актором, типом и хешем payload; повтор с иным содержимым отклоняется. Область действия и срок хранения ключа определяются перед реализацией.

Ответ: `request_id`, `status`, `server_time`, `revision`, результат либо код ошибки. Ошибки: недостаточно ресурсов, нет прав, конфликт версии, цель недоступна, лимит запросов, несовместимая версия. Повтор той же завершённой команды возвращает тот же результат в пределах согласованного окна.

## Снимок и события
Снимок содержит только доступную актору информацию. События имеют `event_id`, revision/sequence и время. Пропуск, повтор и смена подключения обрабатываются явно; при разрыве последовательности клиент запрашивает снимок. Пагинация/область видимости ограничивают размер данных карты.

## Инварианты
Остаток ресурсов ≥ 0; склад не превышает лимит по правилам экономики; отряд не находится в двух местах; событие выдаёт награду не более одного раза; revision монотонна в выбранной области; скрытые данные не попадают в ответы и логи клиента.

## P01-02 должен уточнить
Схемы запросов/ответов, единицы и точность ресурсов (без двоичных float для баланса), диапазоны чисел, область revision, конкурентные команды, авторизацию, совместимость клиента, миграции, правила изменения конфигурации, порядок одновременных событий. Этот документ пока не готовая спецификация API.
